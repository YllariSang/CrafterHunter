# MHW rendering probe v0.2

This is the first composition checkpoint. The opt-in SharpPluginLoader
`OnRender` callback draws a bright green 1 m wireframe cube about 3 m ahead of
MHW's camera using its 3D primitive renderer. Version 0.2.1 derives the centre
ray from the actual view and projection matrices, including reversed-depth
projection. It uses the last successful camera sample and requires the local
bridge handshake and startup grace. The cube is a test shape generated by
CrafterHunter; it is not Minecraft geometry.

The first 0.2.0 screenshots showed green geometry in an expedition but only
partial, off-centre edges. The subsequent 0.2.1 screenshots were taken in
Astera's crowded smithy, where the three-metre cube intersects nearby props
and the floor. A few long edges remain visible. This proves the callback draws
but does not conclusively establish whether the cube is centred or whether
depth occlusion works. Re-test in open space before choosing the compositor
route.

## Prepare

1. Close MHW. From the repository root, run
   `bash tools/prepare-render-probe.sh`. This builds the 0.2 MHW plugin and
   upgrades the managed plugin installation. The script backs up the previous
   DLL under `native/mhw-spl-plugin/build/rollback.*`; the installer verifies
   its marker and refuses to overwrite an externally changed DLL.
2. In MHW Steam Properties, set launch options to exactly
   `DOTNET_ROOT= WINEDLLOVERRIDES="ucrtbase=n,b" CRAFTERHUNTER_CUBE_PROBE=1 %command%`.
   Remove only `CRAFTERHUNTER_CUBE_PROBE=1` to switch the probe off later.
3. Start the bridge from a normal terminal (`bash tools/prepare-play.sh` also
   keeps exactly one Fabric mod in Minecraft's mods folder). Launch MHW and
   Minecraft through the usual profiles. The script and build do not launch
   either client.

## In-game acceptance

After MHW enters an expedition and the bridge handshake and ten-second grace
have elapsed, move to a broad clearing away from walls, NPCs, and props.
Point the camera roughly level across the clearing, then look for the green
wireframe cube near the screen centre. Avoid aiming at the floor or a nearby
object: the cube sits three metres ahead and may intersect them. Move and
rotate the MHW camera. The cube should remain about 3 m ahead.
Check these specific questions and capture screenshots or log lines:

- Does the cube appear at all? If not, inspect
  `nativePC/plugins/CSharp/CrafterHunter/CrafterHunter.runtime.log` for
  `Opt-in cube rendering probe enabled` or `Rendering probe disabled`.
- Does the cube stay centred while rotating? If it is behind the camera, the
  view/projection matrix convention still needs correction. A screenshot
  without the desktop switcher over the game makes this easier to judge.
- Does MHW terrain hide the cube when a wall lies between the camera and it?
  `OnRender` happens after the game frame, so depth occlusion must be observed,
  not assumed from the API name. If it draws through walls, the next step needs
  a depth-aware renderer.
- Does MHW remain stable for five minutes? Report an exception or crash before
  trying a larger rendering experiment.

The plugin defaults to no rendering if the environment variable is absent.
The 0.2.1 placement, depth behavior, and performance are still unverified in
the game.
