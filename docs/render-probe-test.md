# MHW rendering probe v0.2

This is the first composition checkpoint. The opt-in SharpPluginLoader
`OnRender` callback draws a bright green 1 m wireframe cube about 3 m ahead of
MHW's camera using its 3D primitive renderer. Version 0.2.2 derives the probe
direction from the camera's world-space target, draws a small magenta centre
marker, and writes at most twelve position/projection diagnostics to the
SharpPluginLoader log. It uses the last successful camera sample and requires the local
bridge handshake and startup grace. The cube is a test shape generated by
CrafterHunter; it is not Minecraft geometry.

The first 0.2.0 screenshots showed off-centre green geometry. Subsequent
0.2.1 screenshots still showed a single line rather than a cube. The user
confirmed it stays in one direction relative to the player, fails to follow
camera movement correctly, and draws over foreground objects. The 0.2.1
view/projection-derived ray therefore did not fix placement. The primitive
renderer also fails this project's depth-occlusion requirement in the observed
scene. Version 0.2.2 is a targeted placement diagnostic; a separate depth-aware
renderer is still required for Minecraft blocks.

## Prepare

1. Close MHW. From the repository root, run
   `bash tools/prepare-render-probe.sh`. This builds the 0.2 MHW plugin and
   upgrades the managed plugin installation. The script backs up the previous
   DLL under `native/mhw-spl-plugin/build/rollback.*`; the installer verifies
   its marker and refuses to overwrite an externally changed DLL.
2. In MHW Steam Properties, set launch options to exactly
   `DOTNET_ROOT= WINEDLLOVERRIDES="ucrtbase=n,b" CRAFTERHUNTER_CUBE_PROBE=1 %command%`.
   Remove only `CRAFTERHUNTER_CUBE_PROBE=1` to switch the probe off later.
3. Start the bridge from a normal terminal (`bash tools/prepare-play.sh` also
   keeps exactly one Fabric mod in Minecraft's mods folder). Launch MHW and
   Minecraft through the usual profiles. The script and build do not launch
   either client.

## In-game acceptance

After MHW enters an expedition and the bridge handshake and ten-second grace
have elapsed, rotate the camera and walk a few steps. The magenta centre marker
and green wireframe should change with the camera. Then inspect
`nativePC/plugins/CSharp/Loader/SharpPluginLoader.log` for up to twelve
`[CrafterHunter probe]` lines. They report camera position, target, proposed
cube centre, and the loader's `WorldToScreen` projection. Two lines taken
before and after movement are enough to see whether camera state changes.
Check these specific questions and capture screenshots or log lines:

- Does the magenta centre marker track the camera? If not, compare the log's
  camera and target values across movement; a fixed target means the sampled
  viewport is not the active render camera.
- Is the logged screen position near the middle of the viewport? If it is but
  the marker is visibly elsewhere, the primitive renderer is using a different
  projection or viewport.
- Do the green edges still cover foreground objects? If so, continue with a
  depth-aware rendering path for actual blocks.
- Does MHW remain stable for five minutes? Report an exception or crash before
  trying a larger rendering experiment.

The plugin defaults to no rendering if the environment variable is absent.
The 0.2.2 placement and performance are still unverified in the game.
